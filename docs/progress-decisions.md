| 阶段 | 内容 | 验收 |
|---|---|---|
| 0 | `Economy` 与 `Plan` 字段级设计 | 三条约束满足（见 决策/分期与粒度.md），且每个主体有稳定标识符 |
| 1 | 在 dep1ex 上端到端跑通：`Economy` + 不变量 + 一个协调方法 + 最小 `Evaluator` | 冷启动跑出 13 到 14 轮 |
| 2 | 不变量与 `Evaluator` 做扎实 | 四条不变量加五项指标，属性测试覆盖 |
| 3 | 接真实投入产出表（EXIOBASE 或 WIOD），带劳动与排放扩展 | 一条命令从原始数据到可跑的 `Economy` |
| 4 | run manifest 与输出契约 | 长格式 Parquet，每个数字可回溯 |
| 5 | 第二、第三个协调方法（Cockshott 劳动时间、线性规划参照解） | `spec.md` 的抽象判据成立 |
| 6 | 参数扫描 | 场景级并行 |

阶段 1 选 dep1ex 而不是玩具数据或直接上 EXIOBASE，因为它同时满足四条：
真实的已发表数据；小且已解析（`research/bench/repro.py`）；**有已知正确答案**；
字段形状齐全（中间品、自然资源、劳动、私人与公共消费五类价格，见 `repro.py:118`）。
它是检验 `Economy` 字段设计的最便宜的用例，此时改字段还便宜。

技术约束：技术表示用 Leontief（`Technology` 仍是可扩展类型）。
v1 不做算子层，协调方法由学者用任意 Python 实现，见 [决策/协调方法.md](决策/协调方法.md)。

## 待收敛的设计自由度

甲档（推迟就要重写）五条里，三条已于 2026-08-28 收敛：

| 项 | 状态 |
|---|---|
| 协调方法的接口 | ✅ 单层 `solve` + 自愿的 `iterate` 工具 + 可选 `plan_of` |

| 确定性与内容哈希的承诺范围 | ✅ 声明边界 + `check_determinism` 自测工具；哈希只对库自带的实现算 |
| **`Economy` 字段级设计** | ⏸ 阶段 0，要动手画 |
| **`Plan` 字段级设计** | ⏸ 阶段 0，与上一条成对 |

`Plan` 要同时装下三种机制的产出：迭代调价出指示性价格加数量，
劳动时间直接计算出劳动价值加数量，线性规划出数量加影子价格。
不变量检查、指标计算、Parquet 输出全部以它为对象，所以它与 `Economy` 必须一起设计。

v1 自带几种协调方法、错误呈现方式、seed 派生工具。

丙档（机械决策，可自行定夺）：仓库结构（单仓 workspace，maturin 布局）、CI 形状、
包名与模块划分、`CITATION.cff`。
