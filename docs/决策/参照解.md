# 参照解

> 「参照解」对应代码里的 `reference_solution` 与 `ReferenceProcedure`，目标函数对应 `Objective`。
> 定义本身（以目标函数为参数）见 [不变量与指标.md](不变量与指标.md) 2026-09-05。本文记实现层的决策。

## 2026-09-05

### 目标函数既定权重也定分配，两者都是理论承诺

**决策**：`Objective` 协议有两个方法：`weights(economy)` 给最终消费的权重，
`allocate(economy, aggregate)` 把线性规划算出的最终消费总量分到消费单元与公共品。
库自带两个目标：`MaximizeWeightedConsumption`（等分）与 `MinimizeLabor`（给定最终消费下限，
最小化劳动总用量，也等分）。两个都在文档字符串里写明各自承诺了什么。

**Why**：`Plan` 的消费侧是「谁分到多少」，线性规划只算得出总量。总量怎么分是分配理论，
与权重一样是一派主张，所以放进目标对象而不是写死在求解器里。

**排除方案**：

- 求解器把总量记在一个代表性消费单元上 — `Plan` 的形状要为它开特例，且分配理论被藏进了实现
- `targets` 允许落在中间品或劳动上 — 那些量在 `Plan` 的消费侧没有位置，物料平衡从计划上算不回来。现改为报错

### 影子价格取自偶变量，不钳位

**决策**：`valuation["shadow_price"]` 取商品约束的对偶变量，只把 1e-12 以下的噪声归零，
不做 `max(x, 0)`。最终消费下限用变量下界实现，不进约束矩阵。

**Why**：钳位会让「影子价格非负」这条测试变成恒真，符号写反照样绿。
下限进约束矩阵会让对偶向量多出与商品不对应的分量，破坏「一商品一影子价格」。

---

### `linearize` 是含理论承诺的工具，惰性单元系数全 0

**决策**：`linearize(economy, plan)` 把每个生产单元的技术换成 Leontief，系数取 `input_use / output`。
产出为 0 的单元系数全 0，文档说明它在参照解里等于「无中生有」，带权重时线性规划无界。
拒收负产出与溢出的系数。

**Why**：把机制选出的投入比例当成固定技术是一条承诺，不是中性变换。
惰性单元的处理有两种（全 0 或剔除），选全 0 是因为它不改变单元表的行身份，
剔除的责任交给调用方。dep1ex 上最小产出 0.1067，不触发。

---

### 目标函数声明的良构性由库检查，与可选不变量无关

**决策**：`MinimizeLabor` 拒收负的最终消费下限；只带 `final_demand_lower_bound` 或只带 `minimize_kind` 之一的目标函数，
`reference_solution` 报错而不是静默当成最大化。这两条检查的是**声明**的良构性，
不是计划的不变量，所以不受「非负性是可选约束」的限制。

**Why**：第二轮红方实测，负下界让该商品的最终消费为负、用自己的下界补自己的投入，
劳动最小值从 12 报成 6 而 `status` 仍是 `optimal`；半声明的自写目标被当成权重全零的最大化，
返回全零解且 `status` 为 `optimal`。参照解是全库的打分基准，它静默错了没有任何东西会发现。

**How to apply**：按属性识别最小化目标这个契约已写进 spec。学者自写目标带负下界的情形
`reference_solution` 还没拦（只在 `MinimizeLabor` 上拦），下一轮补。

### 抽象判据的第一次检验

**决策**：以 `tests/test_reference.py` 的 dep1ex 用例作为 spec 抽象判据的第一次检验：
parecon 计划与参照解跑在同一份线性化后的 `Economy` 上，经同一组派生访问器打分。
2026-09-05 本机数字：加权最终消费 1.525e8 对 2.158e8，劳动总用量 9.64e4 对 1.00e5，参照解 4.43 秒。

**Why**：判据要求三种机制跑在同一个 `Economy` 上。这次只有两种，且 parecon 跑的是柯布-道格拉斯
经济体、参照解跑的是它的线性化，**不是同一份 `Economy`**，只是同一批单元、商品、消费单元。
判据算部分受检，完整检验要等 Cockshott 劳动时间机制（阶段 5）。
