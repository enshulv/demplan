# 插件边界

## 2026-08-28

### 机制层可插拔，数据模型与不变量固定

**决策**：`Procedure`、`Participant` 行为核、经济体生成器与数据加载器、约束族、附加指标、
输出后端、可视化，这些做成插件。`Economy` 数据模型、守恒律与不变量检查、一组核心指标、
确定性与种子化，这四项固定，不作为插件暴露。

**Why**：本库背负一个通用 harness 类项目没有的负担——跨研究的可比性。
数据模型一旦可插拔，两份结果就不可比，「让研究不再分散」这个目标当场失败。

反过来，机制层必须可插拔，因为在经济学里插件边界约等于理论承诺边界。
换一个效用函数不像换一个日志组件，它是一次理论表态。把这些选择显式化，
插件注册表会长成一张理论景观图。上游实现的问题正是这些假设（收入固定、劳动供给外生、单期）
全埋在代码里，读者看不见。

**排除方案**：

- 一切皆插件（deepseek-harness 的 "Everything is a Plugin"）— 作为内部纪律可取，
  作为对外承诺会伤到目标用户。见下一条决策

**How to apply**：判断某个槽位该不该做成插件，问这一句——不写代码的社科研究者会不会想换它？
会 → 必须能在场景文件里换，且有默认值。不会，但另一个机制学派会 → 第三层插件，
文档面向实现者。两者都不会 → 它是内核，插件化只增加装配负担。

---

### 对外表面走三层渐进披露

**决策**：

1. 场景文件（TOML），零代码
2. prefab 加参数覆写，Python 十行
3. 自己实现 `Procedure` 或行为核

第一层必须能独立完成一篇论文的全部实验。

**Why**：插件化本身不难懂，社科研究者天天在 R 里 `library()`。
劝退的是配置空间——一切可插拔时一切都没有默认值，用户面对几十个槽位，
不知道哪个填错会让结果无声地变成垃圾。

Concordia 的解法是 `prefabs`：内部彻底组合，对外出预装配配方。

**How to apply**：每个 prefab 对应一篇文献的复现，命名如 `hahnel_2021`、`cockshott_cottrell`。
用户从「我要复现这篇」起步，不从空白装配起步。给有主见的默认值，不给几十个平权选项。

---

### 插件系统自带装配期校验与 run manifest

**决策**：每个插件声明它需要与提供什么，整张装配图在开跑前校验。
每次运行产出 run manifest，记录解析后的插件图、版本与内容哈希。

**Why**：缺这两样时，插件化会加剧分散而不是消除它。

装配期校验：不能让一个长时间实验在中途因为「这个 `Procedure` 需要资本存量而你的 `Economy`
没有」而崩掉。Rust 类型系统能挡一部分，但插件边界跨到 Python 后这层保护就没了。

run manifest：没有它，两个研究者悄悄换了一个需求核，结果就不可比。论文引用 manifest 哈希。

---

### 接口函数式，实现可原地可变

**决策**：`Procedure` 的签名形如 `fn step(state: State) -> State`，实现内部用独占借用原地修改。

**Why**：纯函数白送三样东西——可重放、可快照、可时间旅行调试。属性测试也只在纯函数上好写。
上游实现的 TODO 里写着「Add time-travelling」，但状态在可变引用里，做不到。

但纯函数不等于每步复制整个世界。10⁷ 实体上用持久化数据结构会让性能优势全部消失。
Rust 的所有权正好允许「签名是函数式的，实现是原地的」。

---

### 固定项从四项收窄到两项

**决策**：不作为插件暴露的固定项，现为两项：`Economy` 数据模型、确定性与种子化。

原来的四项里，「守恒律与不变量检查」与「一组核心指标」移出固定层，
成为可选工具与由学者声明的东西。

**Why**：两者都带理论承诺，与 [不变量与指标.md](不变量与指标.md) 立的
「理论无关是基础层硬约束」冲突。四条不变量与五项指标各自蕴含的预设在那份文件里逐条列了。

本条只改固定项的清单。上面那条决策的其余部分——机制层必须可插拔、
插件边界约等于理论承诺边界、判断某槽位该不该插件化的那条判准——全部继续有效，
而且「插件边界约等于理论承诺边界」正是本次收窄的依据。

**部分收窄**：本条收窄 2026-08-28「机制层可插拔，数据模型与不变量固定」的固定项清单。

**How to apply**：可比性不再依赖固定指标，改为依赖「同一份 `Economy` + 记录纪律 +
声明的比较基准 + 输出原始到足以事后重算」。
