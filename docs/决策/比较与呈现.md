# 比较与呈现

> 「预设比较项」指库自带、跨机制都算得出的那批量；「差异呈现」指把两次运行的这些量并排摆出来。

## 2026-09-05

### 库不打分，只呈现差异；比什么由预设项加学者配置决定

**决策**：库不对计划打分，也不排名。它做四件事：

1. 算并呈现一批**预设比较项**——跨模型、跨理论都必然存在的量
2. 允许学者**配置**这些预设项
3. 提供**扩展点**，让学者加自己的比较项
4. 某一侧无定义时**留空**，且空与零要能区分

**库不接「替我实现一个非预设项」的请求。** 学者要的项不在预设里，那是他自己的活，
包括去改对面机制的实现让它也吐出这个量。呼声足够大时才升格进库。

**Why**：这条不是新方向，是把 [spec.md](../spec.md) 里一处遗留措辞与项目其余部分对齐。
spec 原来写「三者……由**同一批指标函数打分**」，而同一份 spec 又写着
「库给数字，不给判词」，[不变量与指标.md](不变量与指标.md) 还写着
「不设固定的核心指标，比较基准由学者声明」。**「打分」蕴含库有一把尺，后两条明说库没有。**

「预设项 + 无定义留空」这个形状本身早就定了，见 spec.md 的「差额恒算，命名中性」：
物料平衡、预算、非负性三条无论有没有被设为约束库都算并写进输出，
机制上无定义的除外，且「N/A 不是 0，输出要能区分」。本条把它从差额推广到整个比较面，
并补上「可配置」与「有扩展点」两件。

**排除方案**：

- 库定义一套核心指标并排名 — 判词也是理论，撞 不变量与指标.md 那两条
- 只保证输出格式规整、差异全归学者算 — 「忠实、无偏地呈现差异」这条承诺库就没有兑现的手段，
  学者把申报量减配置量也没人拦

**How to apply**：新增任何一个候选比较项时先问：**它在所有机制上都必然存在吗？**
不是，就不是预设项，进扩展点。

---

### 「效率」不设固定口径

**决策**：库原样呈现墙钟（`RunSummary.wall_seconds`）、轮数（`rounds`，不用 `iterate`
的方法为 `None`）、收敛与发散三态，**不定义「效率」**。口径由学者在比较时声明。

**Why**：墙钟测的是实现不是机制。2026-09-05 实测：同一份代码带不带发散检测差 8% 到 14%，
机器忙闲差 45%。拿它当效率会把工程差异读成机制差异。轮数也不通用——不迭代的方法没有轮数。

两者都不是「跨模型必然存在」的量，所以都不构成预设的效率口径。
这与 [不变量与指标.md](不变量与指标.md)「不设固定的核心指标」一致。

---

### 差异呈现是一个薄组件，不是纯文件格式

**决策**：库提供一个接受两次运行、产出差异的组件。它只做预设项、留空、配置与扩展点，
不做通用比较引擎，也不下判断。

**Why**：预设项要算、要能留空、要能配置，这三件靠「把输出写规整、学者自己 diff」做不到。
而「忠实、无偏」这条承诺需要库有能力**拒绝**一次不该做的比较——两侧都非空但不是同一种量时
（申报量对配置量），逐元素相减会给出一个数，而那个数正是有偏的呈现。

**How to apply**：组件遇到两侧语义标识不同时**拒绝相减并说明原因**，不给数字。
