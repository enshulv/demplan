# 演化规律

> 「演化规律」对应代码里的 `advance`：本期计划执行后，经济体变成什么样。
> **不叫「迭代规律」**——本项目「迭代」已专指一次 `solve` 内部的轮次（收敛轮数、冷热启动），
> 两者混用会让「演化规律错了」和「迭代轮数不收敛」读成同一类问题。

## 2026-08-30

### 演化规律归学者，且是工具的参数，不是核心抽象

**决策**：`advance(economy, plan) -> Economy` 由学者提供，装的是资本积累、技术进步、
资源耗竭、人口变化。它是多期驱动工具的一个参数，**不是核心抽象表的第五行**：

```
run_periods(economy, procedure, advance=..., T=5)
```

不做多期的人根本看不到这个概念。

**Why**：归学者是因为它含理论——投资如何变成产能（哈罗德-多马？内生增长？）、
技术如何进步（学习曲线？研发投入？），每一种都是一派主张。
与提案行为同一个处理：提供工具，不写死。

不列为核心抽象是因为它与 `iterate` 同构。`iterate` 的价值不是替学者跑循环
（他自己写 `for` 一样跑），而是**让库看得见这是一条迭代**，于是轮数与轨迹才存在。
演化规律同理：学者可以自己在外面写多期循环，但那样库看到的是 T 个互不相关的 run，
不知道它们属于同一条轨迹，于是跨期溯源、多期输出结构、跨期不变量三样都不成立。

**How to apply**：静态与滚动由学者选——不传演化规律就是静态，传了就是滚动。
库两者都兼容，跟「不传 `plan_of` 就只有轮数」是同一种可选性。

### 演化规律的错误比协调方法的危险，用跨期不变量对冲

**决策**：工具箱增加一批跨期不变量：累计资源用量不超过初始存量、资本存量非负、
人口守恒、存量等于上期存量加本期净流量。与单期的一样**默认关闭**，按需启用。

**Why**：协调方法算错了，这一期的计划就不对，可能被单期不变量抓到。
演化规律算错了，错的是**下一期的题目**，而下一期的协调方法会对着错题算出一个
完全自洽的答案——所有不变量通过、计划完美可行、图很好看。

具体：资本积累公式里少乘一个折旧率，第 2 期产能偏高 5%，第 2 期的计划完全可行，
一条不变量都不违反；第 3 期偏 10%，第 5 期偏 30%。**误差随期数放大，全程静默。**
这是 [性能架构.md](性能架构.md) 记的那个失效模式的最恶劣版本，
因为它每期都把自己修复成一个看起来正确的状态。

跨期不变量正是这类错误的探针：折旧率漏乘会违反「存量等于上期存量加投资减折旧」这条恒等式。
而**跨期不变量只有在库看得见整条轨迹时才存在**——学者自己在外面写循环，
库每期独立检查，跨期约束没人管。危险来自跨期，对冲工具也只在跨期视角下存在。

默认关闭是为了与单期一致（`不变量与指标.md` 的理论无关原则同样适用于跨期那批：
「资本如何折旧」也是理论）。

**How to apply**：文档里要单独提醒跨期那批的性质——单期不变量违反了学者当场看得见，
跨期违反了他看不见。

### 可比性的锚点是初始经济体加同一条演化规律

**决策**：多期滚动下，可比性的表述从「同一份 `Economy`」改为
**「同一个初始经济体，加同一条演化规律」**。两者的演化规律不同时，
比较的是「协调机制加演化规律」的组合，不是纯机制，而这必须在 manifest 里看得见。

**Why**：滚动多期下只有 `Economy₀` 是共享的，之后就分叉——两个机制导致不同的积累路径，
`Economy₁` 就不一样了。那个分叉本身正是要比较的东西之一（「你的机制五期后产能更高」），
所以不是缺陷。

但若不写明，读者会把全部差异归给协调机制。而复现场景更糟：
复现者不知道原作者用的是哪条演化规律，重建出来的轨迹会完全不同，
**而两条轨迹都看起来是对的**——每期都可行、每条不变量都过。
他会以为差异出在机制实现上，实际上全在演化规律。

**How to apply**：manifest 里演化规律的出处与协调方法**同等对待**，文档里单独提醒。

「可比性靠原始输出」里对可比性锚点的表述。那条的其余部分——
输出要原始到足以事后重算任何指标——不变。
