# 纲领定位

## 2026-08-28

### 本库是民主计划经济的共用学术基础设施

**决策**：本库定位为民主计划经济与参与式计划经济的**共用学术基础设施**，由三部分构成：

1. 机制之间的比较基础设施
2. 计算优化基础设施
3. 一层面向社科研究者的低门槛使用外包装

比较是这套基础设施的一个组成部分，不是它的身份。

**Why**：先前把选项设成「中立比较平台」与「parecon 参考实现」二选一，这个框架本身画错了边界。

「中立平台」把边界画在协调机制的种类上，于是要把市场也收进来才自洽。
「parecon 参考实现」把边界画在单一学派上，于是同领域的别的方案进不来。
边界应该画在**领域**上：民主计划经济。这个领域里有多个互不相容的方案——
参与式计划的迭代调价、Cockshott 的劳动时间直接计算、Kantorovich 式线性规划——
它们需要同一个数据模型与同一套指标才能互相对话，而提供这个正是共用基础设施的职责。

外包装单列成一部分，因为目标用户是社科研究者。[技术选型.md](技术选型.md) 已据此把
Python 定为第一用户接口；本条把它提到纲领层：降低使用门槛是交付目标之一，不是实现细节。

**How to apply**：判断一个功能该不该进库，问「它服务于民主计划机制的实现、比较或可用性吗」，
不问「它中立吗」。

---

### 比较的边界只到民主计划机制之间

**决策**：`Evaluator` 比较的对象限定在民主计划机制之间，集中式最优解作参照。
不实现市场机制。`Economy` 不带货币收支、市场出清残差这类市场专用字段。

**Why**：市场基线的唯一用途是应付「compared to what」这个提问。
在共用基础设施的定位下这个提问已经有两个答案：与同领域的其他机制比，与参照解比。

参照解是比市场基线更硬的基准——它是同一个 `Economy` 上可计算的上界。
市场基线则要额外承诺一整套行为假设（谁是价格接受者、出清怎么定义、预期怎么形成），
那套假设本身会成为争议焦点，把评议意见从「你的机制好不好」移到「你的市场模型公不公平」。

字段层面的后果是确定的：`Economy` 不为市场保留结构，字段级设计可以立即开始。

**排除方案**：见 [被否决/纲领定位.md](被否决/纲领定位.md)

**How to apply**：[spec.md](../spec.md) 的核心抽象判据（三种机制跑在同一个 `Economy` 上）
不受影响——那三种全是民主计划机制。新增机制时先判它属不属于本领域，
不属于就不进 v1，也不为它扩字段。

### 库的责任边界：对过程负责，结果由学者负责

**决策**：库保证的是基础设施的可靠性——数据模型、不变量检查、指标口径、
确定性种子分发、溯源记录。学者用什么协调方法、得出什么结论，由学者自己负责。

**Why**：协调方法是学者的研究内容（见 [协调方法.md](协调方法.md)）。
库既然不替他选机制，就不能替他的结论背书。

比喻是公路：路面平不平由修路的人负责，开多快由司机负责。

这条要写进对外文档，因为用户必须知道库替他保证了什么、没保证什么。
含糊的责任边界在学术场景里的后果是具体的——有人会把「库跑出来的」当成「库认可的」。

**How to apply**：文档里凡是描述保证的句子，都要能回答「这是库那一半还是学者那一半」。

### v1 的价值主张排序

**决策**：按「消除多少重复劳动 × 惠及多少人」排，本库对学者的价值依次是：

1. **数据接入**——把一张真实投入产出表变成能算的经济体，是数周的专门工作，
   每个研究者都要重做一遍，且与机制无关
2. **不变量检查**——学者自己不会写，因为要先知道失效模式存在才会想到写
3. **同口径指标**——可比性的载体
4. **溯源与输出**——让别人能复现
5. **参数扫描**——学者自己能写 for 循环，最低

**Why**：这条排序推翻了此前把机制层当成主战场的隐含假设。
机制是学者本来就要自己写的部分，库在那里的贡献最小；
而数据层是纯重复劳动，贡献最大，却最容易被忽略。

**不适用的情形也要说清**：学者只想在玩具经济体上试一次某机制、不关心与他人比较、
也不打算让人复现时，手写 numpy 更快，本库是负担。
本库赢在三件事同时成立时——要真实数据、要与他人比较、要别人能复现。

**How to apply**：v1 的实施次序按这条排。见 [progress-decisions.md](../progress-decisions.md)。

### 货币存量与交互拓扑推迟到 v1 之后，但现在留标识符钩子

**决策**：`Economy` 在 v1 内不加货币或债务存量字段，也不加主体间的交互拓扑（网络或空间）。
两者推迟到 v1 之后。**但阶段 0 必须给每个主体一个稳定的标识符。**

**Why**：两者都是未来要的——货币存量支撑信用创造与赤字融资实验，
以及 SFC 会计守恒律（见 [不变量与指标.md](不变量与指标.md)）；
交互拓扑支撑基于 ABM 的计划模拟，因为 ABM 的主体彼此作用，
不只是各自对中央信号做反应。

推迟是安全的，按 [分期与粒度.md](分期与粒度.md) 立的判准核过：两者都是**加字段**或
**加一张按主体标识索引的独立结构**，已有的场景与方法一行不用改。
对比真正构成重写的那个例子——「v1 直接把 A 矩阵当地面真相」之所以是重写，
是因为它改的是行的身份，不是加字段。

**稳定标识符是唯一必须现在留的钩子**：没有它，以后挂不上存量，也挂不上网络的边。
代价接近零。

**一处要防的误读**：本文 2026-08-28「比较的边界只到民主计划机制之间」那条排除了
「货币收支、市场出清残差这类市场专用字段」，理由是不做市场基线。
**货币存量不属于被那条排除的东西**——它是计划经济内部的货币安排
（苏联的现金与非现金二元货币、参与式计划的消费信用、Cockshott 的劳动券），
不是市场出清机制。将来加它时不要拿那条决策当拒绝理由。
