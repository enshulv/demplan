# 被否决：不变量与指标

## 2026-08-28

### 库规定一组固定的核心指标

**否决**。

**提案**：`Evaluator` 固定五项核心指标——可行性违反、收敛轮数、劳动成本、
排放对上限、给定社会福利函数下的福利——不作为插件暴露，以此保证跨研究可比。

**当初为什么想做**：`插件边界.md:11` 的推理——数据模型与指标一旦可插拔，
两份结果就不可比，「让研究不再分散」这个目标当场失败。

**排除理由**：五项里条条带理论承诺。「给定社会福利函数下的福利」要先承诺 SWF 形式，
那是规范经济学争议最大的地方；「劳动成本」预设劳动是相关的成本尺度，
而线性规划那一派要的是目标函数值；「排放对上限」预设生态约束采取上限形式而非税或存量约束。

更根本的是：**比较不是库做的，是学者做的**。比较的前提是双方共享一套标准，
而选哪套标准是研究者的判断。库替他选，等于替他决定研究结论从哪个角度成立。

可比性另有出路，不必靠固定指标——见 [不变量与指标.md](../不变量与指标.md)
「可比性靠原始输出」那条。

**复活条件**：无。与理论无关这条硬约束直接冲突。

---

### 要求 `State` 实现一个返回可记录量的方法

**否决**。

**提案**：`iterate` 用的 `State` 必须实现 `record() -> dict[str, float]`，
库每轮调用它，保证每个迭代方法都有轨迹。

**当初为什么想做**：保证轨迹非空。否则学者不提供，收敛曲线就画不出来。

**排除理由**：强制买到的是「非空」，买不到「可比」——键名由学者自己起，
甲报 `max_excess`、乙报 `rmse_price`，两条曲线叠不到一张图上。

而**可比的轨迹只能由库算**，所以正确的做法是可选的 `plan_of=`：
学者给出「本轮状态怎么看成一个计划」，库用自己那套量去量，同一定义、可叠加。

成本面还有一条不对称：**自愿的参数可以后加，强制的接口不能后加**。
今天加一个可选的 `plan_of=`，已有调用一行不改；今天不强制 `record()`、明天强制，
所有已发布的方法当场全断。所以「现在不强制」可逆，「现在强制」不可逆。

**复活条件**：观察到几乎所有方法都在传 `plan_of`，且缺轨迹造成了实际问题时。
届时有证据支撑，而不是靠预判。

### 运行时强制确定性

**否决**。

**提案**：沙箱掉学者代码里的 `random`、时钟、文件访问，从运行时保证确定性。

**当初为什么想做**：`spec.md` 承诺「同种子逐位相同」，而学者的任意 Python 兑现不了。

**排除理由**：两条，任一条都足够。Python 没有真沙箱，做不到。
而且随机化的协调方法是合法研究——要保证的是「给定种子后可复现」，不是「不许随机」。

**复活条件**：无。

---

### 对学者提供的协调方法计算内容哈希

**否决**。

**提案**：按 [可复现性.md](../可复现性.md) 的原措辞，对所有协调方法记录内容哈希，
包括学者自己写的那些，用 `inspect.getsource` 之类取源码后哈希。

**当初为什么想做**：上游那个案例——两版调价规则同名，一版 14 轮收敛、
一版 250 轮不收敛，六年无人察觉。内容哈希是防这个的。

**排除理由**：对学者的代码，库算的哈希是一个**更差的版本控制**。
他的方法在一个仓库里，一个 git 提交涵盖整个仓库、有历史、有作者、有时间，
比库抠出来的一个函数体强得多。而他若根本没发布代码，哈希也救不了——
一串十六进制没有对应物，是死的。

技术上还有一串取不到的情况：lambda、C 扩展、交互式定义拿不到源码；
字节码跨 Python 版本不同；哈希依赖闭包等于哈希整个环境。
取不到时只能记「不可哈希」，而**假的溯源比没有溯源有害**。

责任归属也清楚：「我跑的是不是同一份」由学者的版本控制回答，不归本库管。

**注意这条只否决了一半。** 对**库自带的**协调方法与 prefab，内容哈希仍然必须做——
那防的是库自己漂移：半年后改了 `hahnel_2020_slides` 的实现，
旧场景会静默跑出新算法，名字没变、参数没变、结果变了，正是上游那个失效模式的自制版。

**复活条件**：无。库自带那一半本来就保留，见 [可复现性.md](../可复现性.md)。
