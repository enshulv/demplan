# 被否决：技术选型

## 2026-08-28

### 纯 Rust，不提供 Python 接口

**否决**。

**提案**：只发布 Rust crate，用户用 Rust 写自己的实验。

**当初为什么想做**：单一语言栈，无跨语言边界，类型系统能把非法的插件组合变成不可表达，
不需要额外的 schema 校验层。维护面也小一半。

**排除理由**：目标用户是经济学者与社会科学研究者。他们要的是 `pip install` 之后在 notebook
里改参数重跑。Concordia 与 AgentSociety 都是 Python，不是偶然。
只有 Rust 接口时，本库对声明的目标用户不可用，而「让研究者少花时间」是本项目的立项理由。

**复活条件**：目标用户改为「要部署系统的工程师」而非研究者。

---

### 纯 Python，不用 Rust

**否决**。

**提案**：全部用 Python 加 numpy 实现。

**当初为什么想做**：开发快，用户零安装门槛，numpy 实测单轮 99 毫秒已经够快。

**排除理由**：三条。v2 的 10⁷ 实体需要无 GC 停顿与 SIMD；跨平台逐位可复现在 Python 生态里
难以保证；wasm 出口拿不到，浏览器内的人在环前端就要另写一份内核，两份必然分叉。

**复活条件**：v2 取消，且放弃浏览器内运行。
