# 被否决：研究方法

## 2026-08-28

### 装 JVM 与 Leiningen，跑上游原始代码做交叉验证

**否决**。

**提案**：在本机安装 JDK 与 Leiningen，让 `pequod-cljs` 跑上游已发表的 `dep1ex` 数据，
拿到它自己的迭代轮数，用来定位「我方重实现得 155 轮、论文称 6.5 轮」这个差距的来源。

**当初为什么想做**：这是唯一能直接比对上游代码行为的路径。差距既然不可能来自浮点差异
（同为 IEEE754 双精度，`Math/pow` 与 libm 差异在 1 ulp 量级），就必然是语义或参数差异，
而跑原始代码能精确定位是哪一条。

**排除理由**：那个差距已经被更便宜的实验解释掉了。冷启动与热启动的对照实验
（两分钟机时，不需要任何 Java）显示：热启动 7 到 8 轮，冷启动 54 到 155 轮，
而上游自己记录的数字也是同样的分布。「6.5 轮」是热启动数字，不是语义 bug。

剩下的唯一悬念是「原版的冷启动是不是也是个位数」，而这一条有两个独立实现都给出否定答案
（作者自己的新代码 41 到 96 轮，我方 54 到 155 轮）。举证责任已经转移，
写信问作者比跟工具链搏斗更快。

**复活条件**：需要逐位比对上游中间结果时；或者作者答复表明原版冷启动确实是个位数，
需要定位差异来源时。
