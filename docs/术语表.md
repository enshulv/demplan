##### 1.2 视语境判断（有时是标准词，有时是比喻）

| 词 | 什么时候可以留 | 什么时候要换 |
|---|---|---|
| 链路 | `调用链`、`链路追踪` 是业界通用 | 单独当「路径」用时 → 路径、流程 |
| 心跳 | heartbeat 是标准协议词 | 泛指「定期确认」时 → 定期回报、存活探测 |
| 护栏 | guardrail 在 CI/权限语境算通用 | 泛指「限制」时 → 检查、限制 |
| 骨架 | scaffold / skeleton 在代码生成语境通用 | 泛指「大致结构」时 → 结构、框架 |
| 颗粒度 | 粒度（granularity）是标准词 | 更好的写法是直接写「按什么分」 |
| 落地 | **一律换** | 实作、上线、执行、写进代码——按语境挑 |

##### 1.3 保留（已成文定义的流程词汇，有单一真源可查）

红方、蓝方、棒、派发、画靶、假绿、覆盖真空、三桶分诊、变异验证、盲写、
真源、基线、接缝（seam，业界标准测试术语）、收敛、复用、诊断。

这些和「水位」的区别：**它们在某支 skill 或某份文档里有定义**，读者查得到。
新造一个没有定义的词才是问题。

##### 1.4 领域词，照常用

你所在项目的业务术语照常用——那是读者沟通的基础，不是比喻，也不需要解释。
判断方法：这个词是这个行业里的人本来就在讲的，还是我为了省事编的？
前者留，后者换。项目有哪些领域词，写在该项目的 `docs/术语表.md`。

##### 1.5 常用技术术语的中文写法

**同一个概念，全篇只用一种中文写法。** 混用是最常见、也最不被察觉的可读性损失——
「快取」和「缓存」交替出现时，读者会以为你在讲两件事。

台湾与大陆的技术中文差异很大。下表列出两种常见写法，**skill 层不替项目决定选哪种**：
每个项目挑一种，写进该项目的 `docs/术语表.md`，之后不再改。

> 🔴 **定案前先数一遍既有文档，别照惯例拍。** 项目里已经用得多的那个通常就该赢——
> 改动最小，而且它往往有你不知道的理由。数完还要看**这两个词是不是根本指两件事**：
> 「例外／异常」可能一个是 exception、一个是原厂规格用语；
> 「依赖／相依」可能只是名词与状态的词性差别。把这两类当成混用去统一，是在制造错误。
> 计数时**记得排除你正在写的那份术语表**——表里列的对照词会把自己算进去。

###### 不译，直接用原文

`API` · `SDK` · `CLI` · `HTTP` · `JSON` · `SQL` · `URL` · `webhook` · `payload` · `commit`

这些译过来反而更难懂。用原文时**大小写与拼写固定**，别一会儿 `Json` 一会儿 `JSON`。

###### 几个词的用法有明确规定（Google 手册）

| 词 | 规定 |
|---|---|
| **API** | 指整套 web API 或某语言的 API。**不要拿 API 指某一个方法或类别** |
| **CLI** | 不要用 CLI 泛指命令行介面，写出是哪一个 |
| **deprecated（已弃用）** | 意思是「建议不要再用，且即将不可用」。**不要拿它指已经删除或已关闭** |
| **canary** | 不要当动词用。能避就避，改写成「先放一小部分流量试」 |
| **limit / quota** | 写清楚是哪一种，例如「用量上限」「服务上限」 |
| **sanity check** | 换成「验证」「校验」 |

> 拼写与大小写另有一套规则（`login` 一个词、`log in` 两个词、`backend` 不加连字号、

##### 2.5 英文拼写与大小写

写英文识别字、英文 commit message、对外英文文档时用。中文写法见 [1.5](#15-常用技术术语的中文写法)。

**动词两个词、名词一个词**：log in / login · sign in / sign-in · set up / setup ·
back up / backup · start up / startup · time out / timeout · run / runtime。
`sign in` 优于 `log in`。

**一个词，别拆也别加连字号**：`backend` · `frontend` · `checkbox` · `email` ·
`filename` · `hostname` · `namespace` · `endpoint`。
**两个词**：`data center`。

**小写**：internet · open source · the cloud · boolean。
不要拿 `cloud` 当某个云产品的简称。

**`plugin`** 名词、**`plug-in`** 形容词、**`plug in`** 动词。

> ⚠️ `backend`、`frontend`、`checkbox`、`email`、`filename`、`hostname`、`namespace`、
> `endpoint`、`data center`、`login`、`plugin` 与全部大小写规则是原文逐字写明的。
> `setup` / `backup` / `startup` / `timeout` / `runtime` 属同一模式但未逐条核对，
> 有疑虑时回 `developers.google.com/style/word-list` 查。

##### 2.6 缩写

- **读者可能不熟的，首次出现时展开**，缩写放在后面的括号里：*Border Gateway Protocol* (*BGP*)。
  之后一律只用缩写
- 首次出现在标题里时，在标题下的第一段展开
- **几乎不用展开的**：AI、API、DVD、HTML、PC、RAM、REST、URL、USB；
  档案格式（PDF、XML）；单位（MB、MiB、GB、GiB）
- **展开不一定有帮助**——写出 portable document format 并不会让人更懂 PDF
- **不要拿缩写当动词用**
- 缩写中间不加句点
- 不用网络缩语：tl;dr、ymmv、RTFM
- 不因为缩写是大写就把展开后的词也大写
- `a` / `an` 看**发音**不看字母：a SQL、a FHIR、an SAP
- 不用 `i.e.` / `e.g.`，改用 `that is` / `for example`

| 词 | 定义 |
|---|---|
| 协调方法（`Procedure`） | 给定全部提案，产出新信号或最终计划的那套办法。上游那条 `w = v(1.05 − 0.5ᵛ)` 调价规则是它的一个实现。由学者提供，见 [决策/协调方法.md](决策/协调方法.md) |
| 冷启动 | 所有指示性价格从统一初值开始的一次计划过程。上游文献称 Year One |
| 热启动 | 承接上一期收敛价格、只对指数施加扰动后重新计划。上游文献称 Year Two |
| 指示性价格 | 参与式计划中由迭代协调局发布的社会成本估计值，不是市场价 |
| 迭代协调局 | IFB（Iteration Facilitation Board），发布并调整指示性价格的程序 |
| 禀赋 | 自然资源与劳动的外生供给量。上游数据文件不含此参数，但论文正文给了值（1000），且经倒推确认，见 [研究/复现记录.md](研究/复现记录.md) |
| 参与者 | 提出提案的经济主体。v1 是部门，v2 是工人议会与消费议会 |
| 机制层 | 可插拔的部分：协调程序、行为核、生成器、约束族、指标。与之相对的是固定的数据模型与不变量 |
| 参照解 | 用凸优化求解器算出的集中式最优解，作为去中心化程序的打分基准 |
| prefab | 按文献预先装配好的一套配置（协调方法、参数、启用的约束集）。命名带出处与年份，如 `hahnel_2020_slides`。**理论承诺归 prefab，不归库** |
| 不变量工具箱 | 可选约束的集合。学者按需启用，逐条加上去实验就逐步变严格。不是硬闸 |
| 差额 | 某条约束被违反的程度，库恒算并写进输出。**用「差额」不用「违反」**——同一个数字对做信用创造实验的人是研究对象，不是缺陷 |
| 比较基准 | 学者在做比较时声明的那个量。库不规定，声明进 run manifest |
| SFC | 存量流量一致（stock-flow consistent）。会计部分作为可选守恒律进工具箱，行为方程归学者 |
| 迭代 | **专指一次 `solve` 内部的轮次**（收敛轮数、冷启动、热启动）。跨期推进不叫迭代，叫演化 |
| 演化规律（`advance`） | 本期计划执行后经济体变成什么样：资本积累、技术进步、资源耗竭、人口变化。归学者，是多期驱动工具的参数，不是核心抽象。**不叫「迭代规律」**，避免与上一条撞 |
| 实物层 / 扩展层 | `Plan` 的两层。实物层是配置（产出、投入用量、消费、禀赋使用），理论无关；扩展层是估值量（价格、劳动价值、影子价格），机制特有 |
| 消费额度 | dep1ex 里的 `income`。外生给定的**流量**，不是可累积的货币存量。v1 不含货币存量，两者别混 |
| Cybersyn | 智利 1971–73 年的经济控制项目（西语原名 Proyecto Synco），民主计划经济唯一一次进入生产运行的尝试。下含 CHECO、Cyberstride、Cybernet、Opsroom 四个组件 |
| Cyberstride | Cybersyn 的统计预测与预警组件。本库名取自它，见 [决策/项目命名.md](决策/项目命名.md) |
| CHECO | CHilean ECOnomy，Cybersyn 的经济仿真组件。功能上与本库对应，但没有拿它当名字 |

收录判准：这些词或者已经写进设计文档并反覆出现，或者在公开资料里查不到统一用法。

## 二、本项目覆写基底的判定

| 词 | 判定 | 理由 |
|---|---|---|
| 冷启动 / 热启动 | 照常用 | 数值优化领域的标准词（cold start / warm start），指「是否复用上一次的解作为起点」，不是自造比喻 |
| 禀赋 | 照常用 | 经济学标准术语（endowment） |
| 影子价格 | 照常用 | 线性规划标准术语（shadow price） |
