# 检核

前面三条轴（当前 / 历史 / 状态）都靠写的时候是对的。时间一长它们会漂：
入口文件停在旧架构、决策拍了板没落地、索引指向已搬走的文件。
任务完成时的记录触发点发现不了这件事——那些触发点挂在「有改动」上，
而漂移发生在没人回头看的地方。

方法与逐项清单见 skill `my-periodic-review`。本文只记本项目的落点与状态。

## 两条线

| 目录 | 周期 | 范围 |
|---|---|---|
| `上下文检核日志/` | 每周 | 入口文件准不准、决策落地没、索引有无孤儿链接 |
| `评估报告/` | 每月 | 架构有没有漂、测试网是不是虚的 |
| `评估报告/证据/` | — | 每个分数背后的原始量测 |
| `评估报告/工具/` | — | 可重跑的量测脚本 |

## 四条规矩

- 十分制固定标尺，每次沿用同一把。改尺等于作废整条时间序
- 每个分数绑一个本次实测的数字。拿不到数字写「未量测」，不给印象分
- 量测指令固化成脚本放 `评估报告/工具/`，不留在对话里
- 时钟只由检核实跑完成推进

检核只评估不修改。上下文线是例外，它查出问题当场改。
发现要编号、可追踪，下一期逐条更新状态；判定不做的走被否决留存，不允许静默消失。
