## blocking[]

### B1. dep1ex 加载器把 `:product` 编号并进 `n_goods`，凭空造出带禀赋的商品，任何调价机制永不收敛

`crates/cyberstride-core/src/dep1ex.rs:852-865`（`largest_commodity_number`）把 `units.product` 与 `units.input_number` 一起取最大值。
`:product` 对 `:industry 0` 编的是私人品、对 `:industry 2` 编的是公共品，与中间品／自然资源／劳动不共享编号空间。
参考 `research/bench/repro.py:223` 只用投入段：`n_goods = int(wc["coef"].max()) + 1`。

触发：任一档案里 `max(:product) > max(投入编号)`。dep1ex01–05 五类各 100 种，看不出来。
后果：多出来的自然资源与劳动带 `endowment`、无任何投入与消费指数，失衡恒为 200%，价格逐轮下调但需求永远是 0。

实跑（`probe_b3.py`、`probe_b4.py`，n_priv=4、n_pub=2、投入编号只到 3）：正确布局 15 种商品，实际 18 种，13 号与 17 号是幻影；250 轮不收敛。

没有测试抓到，因为 `tests/test_core_load_dep1ex.py:63` 的 `reference` fixture 照抄了实现的规则
（`n_goods = int(max(wc["coef"][wc["mask"]].max(), wc["product"].max())) + 1`），而 `tests/reference/dep1ex_numpy.py:83` 用的是参考规则。
`crates/cyberstride-core/tests/load_dep1ex.rs:8-11` 的 fixture `max(:product)=2 < 3`，分辨不出两条规则。
变异 `rs-ngoods-input-numbers-only`（换成参考规则）存活，全部执行者绿。

### B2. `Economy` 宣称的柯布-道格拉斯技术不是 dep1ex 的技术：真实生产函数带 effort 因子，`Plan` 里没有它

上游 `upstream/pequod-plus/src/clj/pequod_plus/csvgen.clj` 的 `solution-3` 与 `solution-4` 除 `output` 与 `x_j` 外还返回 `effort`（八份全部返回）。
把上游 effort 表达式转写后实测 `max |lnQ − ln(a · effort^c · Π x^b)| = 8.9e-16`（`probe_e.py`）。
即 dep1ex 的生产函数是 **`Q = a · e^c · Π x_j^{b_j}`**，`c` 是 effort 在生产函数里的指数。

后果（`probe_d.py`，dep1ex01 收敛计划）：`output / (technology_scale · Π x^input_coefficient)` 最小 1.0015、中位 1.0863、最大 1.3363；
只有 34/30000 个单元在声明的柯布-道格拉斯关系 1% 以内。
`tools.cobb_douglas.cost_minimizing_inputs_flat` 在同一个 `Economy` 上算出的投入组合与 prefab 的不同，没有任何东西提示学者。
dep1ex 档案每个单元都带 `:effort 0.5`，加载器丢弃。

### B3. `run(HahnelSlides2020(), …)` 会在计划全是 NaN 的情况下报告 `converged=True`

`hahnel_2020_slides.py:122` 用 `np.nanmax(imbalance)`；供给或需求出现 `inf` 时 `_relative_imbalance` 给 `inf/inf = NaN`，被当成完全平衡。
`iterate` 的发散检测只在给了 `plan_of` 时才开，prefab 默认 `record_trajectory=False`。

触发：闭式解分母 `D = effort_c − effort_k + effort_k·Σb` 略小于 0。合成经济体把单元 0 的 `effort_c` 设成 `k − k·B − 1e-5`（`probe_g3.py`）：
`converged=True, rounds=2`，`plan.output` 全 NaN，`Plan.validate` 抛 `SchemaError`。`record_trajectory=True` 时 `converged=False, rounds=1`。
参考 `endowment.run` 在同一经济体上给出同样的假收敛（差分看不见）。dep1ex01–05 上 `|D|` 最小 0.382，这条在已发表数据上不是活的。

### B4. 公共品的物料平衡无法从 `Plan` 重建，README 的示例对公共品恒为 0

`hahnel_2020_slides.py:121` 把 `provision` 定义成公共品的供给，README「十行」的 gap 对公共品恒等于 0。
实跑（`probe_f.py`，dep1ex01）：README gap 在公共品上 max 0.0；机制自己量到的公共品失衡 max 0.0348、mean 0.0329，100/100 超过 1%。
`Plan` 没有字段记录消费者对每种公共品要了多少。撞 spec「能不能从输出重建出任何一个指标」。

### B5. 分段商品编号从不做本段边界检查，越界会静默串进邻段

`dep1ex.rs:767`（`base + product − 1`）与 `:775`（`segment_base + value − 1`）不检查编号落在本段长度内。
实跑（`probe_j.py`，n_priv=n_pub=2，n_goods=3）：私人单元 `:product` 越过私人段 → 产出商品类别变成公共品；中间品投入编号 0 → 落到公共品。
`commodity_kind` 是 `endowment_use`、物料平衡、公共品定价的分派依据。无测试覆盖。

## 量具备注

运行器逐字节还原时若落在同一秒，带变异的旧字节码继续被用。红方第一轮有两条假击杀因此而来。
`cd-share-not-normalised` 是等价变异（`log(B)` 在两项里抵消，实测 2000 组随机输入产物差 1.4e-14），不是缺口。
