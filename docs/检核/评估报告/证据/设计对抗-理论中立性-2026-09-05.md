# 设计对抗审查：理论中立性 — 2026-09-05

审的是 `cc43149` 的公开表面。判据出自 `决策/纲领定位.md` 2026-09-05：
理论无关不是「不带理论」，而是把理论做成可选工具、并把它蕴含的立场明确写给学者。
发现分四类：夹带 / 不可选 / 不透明 / 虚报。**只读审查，未改任何文件。**

审查员是无本会话上下文的独立子 agent，与代码对抗审查分开进行。
下列每条的引文与实测均由主 agent 复核，标注了复核方式。

## 虚报[]（宣称了没施加、或施加了没后果的承诺；最严重的一类）

| # | 发现 | 复核 |
|---|---|---|
| V1 | `reference.py` 模块文档写「**Nothing else is imposed**」，实际硬编码四条：非负性（`bounds` 全 `(0.0, None)`）、自由处置（约束用不等式）、期内封闭无库存（约束无存量项）、规模报酬不变且无产能上限（变量无上界）。前三条正是 `不变量与指标.md` 点名「不能设为前提」的理论承诺 | 主 agent 已核引文与 `bounds()` |
| V2 | `Objective.weights` 邀请学者「returns zeros and carries its own attributes instead」，但 `reference_solution` 只认 `final_demand_lower_bound` + `minimize_kind` 一对属性。**零对属性静默放行**：自写目标拿到 `status=optimal`、`value=-0.0`、产出全零 | 主 agent 实测复现 |
| V3 | `_require_consumable_support` 由 `MaximizeWeightedConsumption.weights` 自己调用，参照解那一层对极大化的 weights 没有复查。自写目标把权重放在劳动上，`objective_value=300` 全部来自计划里不存在的量 | 未独立复现；与 V2 同一机理 |
| V4 | README 写「the check is the reason a plan built for one economy cannot be quietly aggregated against another」，而 `_require_conformable` 只比形状与 dtype。两个同形状、产出商品对调的经济体互相接受对方的计划，`validate` 都过 | 主 agent 已核引文与实现 |

## 夹带[]（基础层或绕不开的路径上带着一派假设，未告知）

| # | 发现 |
|---|---|
| J1 | `linearize` 把柯布-道格拉斯的规模报酬递减静默换成规模报酬不变（系数取 `input_use/output`，`technology_scale` 置 1）。README 明写的路径就是「CD 经济体 → `linearize` → 参照解」，所以基准系统性高于原技术能达到的水平，离锚点越远高得越多。文档写了锚点承诺，规模报酬只字未提 |
| J2 | `linearize` 把工人议会选出的 effort 折进投入系数：effort 越高，线性化出来的技术越好。`Plan.extra["effort"]` 被丢弃，返回的 `Economy` 不记得锚在哪。跨机制比较在这里静默失效 |
| J3 | `Plan.endowment_use` 焊死「禀赋 = 自然资源与劳动」，文档以事实语气写「Other commodities are zero: they are produced within the period」——这是 schema 不强制的断言。学者用 `endowment` 列放跨期库存（库留给他的唯一位置）时，供给侧全额计入而使用侧按类别丢弃，两边不闭合 |

## 不可选[]

| # | 发现 | 复核 |
|---|---|---|
| B1 | `CommodityKind` 与 `TechnologyKind` 是封闭枚举（Python 与 Rust 两侧白名单），而 README 写「A new class is a new marker value, not a new column」、spec 写「可扩展」。库自己点名的两项未来扩展（排放、货币存量）现在都进不来。另外「一商品一类别」让双重用途商品（电力既是中间品又是消费品）只能二选一 | 主 agent 已核引文与两侧校验 |

## 不透明[]（承诺是真的，但没写在学者读得到的地方）

| # | 发现 | 复核 |
|---|---|---|
| T1 | ✅ **已修（2026-09-06）**。`check_determinism` 不比 `Plan.extra`，README 却写「compares the plans bit for bit」。`consumer_demand` 每次不同的方法会被报成 `identical=True` | 主 agent 已核引文与 `checks.py`；**代码红方总检察 2026-09-06 独立又撞上一次**，两棒互不知情，见 决策/数据模型.md 同日 |
| T2 | 参照解的计划 `extra` 是空的，README 自己的物料平衡配方在库自己的基准上抛 `KeyError: 'consumer_demand'`。库内两个计划生产者用两套需求侧记录约定 | 主 agent 实测复现 |
| T3 | `commodity_id` / `unit_id` 被称作 stable identifier，实际强制等于行号。演化规律增删任何一行都会给其后全部行重新编号 |
| T4 | 平均分配是分配主张：`MaximizeWeightedConsumption` 写了，`MinimizeLabor` 走同一个 `_split_equally` 却一字没提。且 `n_consumers` 数的是消费议会不是人，prefab 的公共品规则却把它当人数用 |
| T5 | `MinimizeLabor` 把所有劳动商品按 1:1 相加，即各类劳动按小时完全通约——这正是劳动价值论内部最著名的未决问题 |
| T6 | `load_dep1ex` 的 `endowment=1000.0` 决定整个经济体的约束水平（500 与 1000 下 3% 收敛轮数是 45 对 23），函数文档写了，README 的十行示例没写 |
| T7 | `provision` 一种公共品一个标量，即萨缪尔森式纯公共品；区域性或分级供给物理层表达不了。`total_consumption` 只覆盖私人品，按人均口径用它会系统性漏掉公共品 |
| T8 | `initial_price = 700.0` 的出处（论文正文）没写在文档字符串里，而 `threshold_pct` 写了 |
| T9 | `ReferenceProcedure` 无条件宣称「The linear program is deterministic」，实际由 SciPy 调用的 HiGHS 提供，跨版本与构建不受本库控制 |
| T10 | `valuation` 三个价格类键并列出现，读起来像可互换的「价值」，实际单位与归一各不相同（指示价格只在整体缩放意义下有定义、LP 对偶是「目标值/单位商品」、劳动价值是时间） |

## 不可避免但已告知[]（正面结论，节选）

`input_use` 存储而非派生、`linearize` 的锚点承诺与惰性单元处理、
`cost_minimizing_inputs` 与 prefab 不一致的提醒、`iterate` 的轮数定义、
`converged`/`diverged` 三态、`check_determinism` 是工具不是闸门、
**收敛判据完全交给学者（理论无关做得最干净的一处）**、发散只认非有限值的准确措辞、
`PriceRule` 只读入参、`CouncilModel` 的承诺清单、`split_seed` 的前缀链性质、
单元恰好一种产出（已作为 v1 范围限制告知）。
